== 4. What the sender can and cannot do today (no code was changed)
   EvnRmnMr: the planner gives every validator of a stratum the same quota, so EvnRmnMr would get the supplementary Firedancer quota too.
     `sender session` has NO --selection flag and its workers pass none (main.rs Cmd::Session, session::worker_args); `live` then takes the newest data/snapshots/selection_*.json (latest_selection, by file name).
     No code change is needed. The copy analysis/sim/results/sessions/selection_amendment1_no_EvnRmnMr.json (the original selection_20261022T163227Z.json without EvnRmnMr) is stored in the repo and copied byte for byte to data/snapshots/selection_20261029T112100Z_amendment1_no_EvnRmnMr.json just before the session: it sorts after the original and is what session and workers load.
     It is NOT kept in data/snapshots between sessions, because tagged tools and tests (session_cmd.py, sessions.py, independence.py, test_session_cmd.py) read the newest selection_*.json there. `sender plan --selection <file>` takes a file explicitly.
   X gaps: the gap of an X window is x_gaps_ms[(X windows done) mod 5] (planner.rs line 285) with x_gaps_ms = [0, 10, 25, 60, 120] fixed in arms.rs. There is no switch: restricting to 0, 10, 25 ms needs a change in crates/ (not made).
   Without that change the supplementary X windows would again go to all five gaps in rotation (60 and 120 ms: 6 and 0 usable of 36 attempted each so far; 33 each without EvnRmnMr).
   Hours at supply assume the planner can use every leader window of a validator (no pacing or 5 s spacing skips), so they are a lower bound; the 44 an hour is the rate session 4 achieved.
   Pooled Agave: the same quota goes to 5Us18hLZ and 7QQGNm3p; the pooled cell target is met by the pair, 5Us18hLZ is the supply bottleneck.
